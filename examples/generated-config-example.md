# Example: Generated Config

A worked example of generating an MCP client configuration with
`render_config.py`. It uses placeholders only and assumes no specific machine.

## Preview with a dry run

Always preview before writing. A dry run prints the activation summary and the
rendered config but writes nothing:

```bash
python3 scripts/render_config.py --profile local-inspect --client continue --dry-run
```

Output:

```text
Activation summary — profile: local-inspect
  intent: Local workspace and repository inspection only.
  allowed capability classes: passive
  write actions: disabled
  servers selected: 4
    - filesystem-controlled  [modifying]  mode=inspect (controlled: 3)
    - git-controlled  [modifying]  mode=inspect (controlled: 6)
    - sequential-thinking  [passive]  mode=enabled
    - sqlite-controlled  [modifying]  mode=readonly (controlled: 4)
  note: activation policy and scope controls are declarative intent, not runtime enforcement.

--- rendered config ---
# Generated by cris-mcp-toolbelt render_config.py — do not edit by hand.
# Regenerate with render_config.py to change.
mcpServers:
  filesystem-controlled:
    command: npx
    args:
    - -y
    - '@modelcontextprotocol/server-filesystem'
    - '{WORKSPACE_ROOT}'
  git-controlled:
    command: uvx
    args:
    - mcp-server-git
    - --repository
    - '{WORKSPACE_ROOT}'
  sequential-thinking:
    command: npx
    args:
    - -y
    - '@modelcontextprotocol/server-sequential-thinking'
  sqlite-controlled:
    command: uvx
    args:
    - mcp-server-sqlite
    - --db-path
    - '{SQLITE_DATABASE_PATH}'
--- dry run: no file written ---
```

## Reading the output

- **servers selected** — the catalog servers the profile may use. A server
  appears if it lists the profile in `allowed_profiles`.
- **`[modifying]`** — the server's `capability_class`, its capability *ceiling*.
  A write-capable server can still appear under an inspect-only profile; its
  `mode` in the activation summary shows the conservative default selected
  from the catalog.
- The rendered `mcpServers` entries are real client runtime blocks containing
  `command`, `args`, and optional `env`.
- **`(controlled: N)`** — the count of `controlled_capabilities` the server
  declares — capabilities that require intentional activation.

## Writing the config

Drop `--dry-run` and add `--output` to write the file. An existing file is
backed up to `<file>.bak` first:

```bash
python3 scripts/render_config.py --profile local-inspect --client continue \
    --output {TARGET_REPOSITORY}/{MCP_CONFIG_DIR}/cris-mcp-toolbelt.yaml
```

Or use the workspace enablement wrapper:

```bash
{PROJECT_ROOT}/scripts/enable_for_workspace.sh {TARGET_REPOSITORY} local-inspect
```

## Selecting specific servers

To render only chosen servers, pass `--servers`. Requesting a server the
profile is not permitted to use is an error:

```bash
python3 scripts/render_config.py --profile writer \
    --servers filesystem-controlled,git-controlled --dry-run
```
